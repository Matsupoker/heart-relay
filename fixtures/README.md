# 架空利用者200名フィクスチャ

すべて架空のシミュレーション用データです。実在の利用者・職員・医療機関・事業所の情報は入力していません。氏名は読み付きの語彙を組み合わせて作成し、施設・町名は造語です。一般的な人名の偶然の一致は、実在人物との関連を意味しません。担当職員15名のみ、本リポジトリで架空と明記された `backend/src/seedData.js` の氏名を再利用しています。

## 形式の出典

正本は [Matsupoker/HARMONIZE の d87c5e905d6fa7268f0c343275200c824e8f12ec](https://github.com/Matsupoker/HARMONIZE/tree/d87c5e905d6fa7268f0c343275200c824e8f12ec)、ブランチ `codex/harmonize2-sds-csv-v1`、アプリ版 `2.2.0-mvp.1` です。旧Excel/VBA版の `main` は参照していません。

確認したコードは `app/src/domain/{types,masters,text,users}.ts`、`app/src/persistence/backup.ts`、`app/src/export/{marsCsv,sdsCsv}.ts`、`app/src/import/{wiseManXls,birthDate}.ts`、`app/src/test/fixtures.ts`。仕様書 `docs/spec/0101-harmonize2-mvp-detailed-specification.md` の13項目、DS-023-01、DS-025-01、DS-028-02とも照合しています。

JSONはUTF-8 BOMなし・LF、`JSON.stringify(file, null, 2)` と同一（末尾改行なし）。CSVはUTF-8 BOM付き・CRLF（最終行末を含む）。MD・スクリプトはUTF-8 BOMなし・LFです。

## 再生成・検証

Node.js 22で、リポジトリ直下から実行します。`npm install` は不要です。

```sh
node tools/fixtures/generate_fictional_users.mjs
node tools/fixtures/validate_fixtures.mjs
```

生成は既存のデータ4ファイルを上書きします。README・SCHEMAは静的な説明です。seedは `0x48523200`、日時は `2026-11-05T00:00:00.000Z` 固定。PRのseedDataを入力とし、時刻・ネットワーク・実在記録を使わず、同じNode/ICU環境で同じバイト列を生成します。CSV順序はHARMONIZE2同様、実行環境の日本語 `localeCompare` に従います。

姓72件・男性名70件・女性名70件に読みを併記しています。漢字からの読み推測は行いません。検証スクリプトは生成スクリプトを読み込まず、`parseBackup` の検証規則と以下のフィクスチャ固有規則を独立して確認します。違反は列挙して非0終了します。

## 整合性規則と分布

- 利用者IDは欠番のある `0001`〜`0480` の200件、一意・4桁文字列・ID昇順。氏名は半角空白1個で区切り、同姓同名を別IDで2組用意しています。
- 女性125名（62.5%）、男性75名。生年月日は1930〜1961年で、2026-11-05時点の年齢65〜96歳。65歳条件を満たすため1961-11-06以降生まれは作りません。
- カナは半角カタカナ、濁点・半濁点は分離。通常は `sei` / `mei` と一致。3名だけ空白のないカナと `review: { kanaBoundary: true }` を持ち、`sei` / `mei` は空。それ以外の `review` は `{}`。
- 利用中150名は正本の `usageStatus: "利用中"`、中止中30名・終了20名は `usageStatus: ""`。状態・出欠・移動手段はそれぞれ別の項目です。
- 居宅8件・各CM2名の計16件。利用者のCM所属と居宅は必ず一致。居宅人数は50/36/28/24/20/18/14/10名。
- 担当スタッフ15名に全員を割り当て、1名あたり13〜14名。標準移動手段8件はコードと同じ順・名称、人数40/40/20/14/13/13/20/40名。
- 自宅150名、架空施設18/17/15名。標準の施設名称は使いません。`1.自宅` のみ指定どおり共通。カウンタは8/16/15/4/8で最大連番と一致。
- 初回登録は2025-04〜2026-10の19回の月次取込日時に集約。`statusSince` は初回登録日以降かつ基準日以前。
- 利用中だけ月〜土の1〜3曜日を持ちます。曜日別人数は月35・火34・水35・木35・金36・土35。中止中・終了は空配列。自宅はコース1〜4を設定し、施設は空。送迎注意は40名（20%）。
- 出欠は全200名、一意なIDで保持。2026-11-10の予定34名のうち出席31名・欠席3名、残る166名は対象外。欠席理由は短い架空の内容です。
- CSVは利用中だけをカナ→IDの日本語比較順で出力。SDSのスタッフは全件をID昇順で末尾に置きます。引用符はカンマ・引用符・CR/LFがある値だけに付け、引用符は二重化します。

依頼文の「2026-11-10（月）」は暦と不一致のため、固定日付を優先して**火曜日**の予定を使います。コードの `sortUsers` はIDの同値判定にも `localeCompare(..., 'ja')` を指定しており、それに合わせています。`parseBackup` 自体は空欄の性別・生年月日や緩い日時形式も許容しますが、このデータの検証は依頼の非空・範囲・ISO正規形に厳密化しています。
