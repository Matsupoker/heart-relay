# HEART RELAY（仮）

**介護現場の情報集約・判断・個別伝達システム**

HEART RELAYは、介護現場で発生するさまざまな連絡事項を整理し、必要な情報を必要な職員へ届ける仕組みを検証するプロジェクトです。

単に全員へ同じ情報を一斉送信するのではなく、職種・担当業務などに応じて届け先と内容を選別し、重要な情報が埋もれないことを目指します。

本リポジトリは、**Built with Claude: Japan 2026** に向けた新規開発用の公開リポジトリです。現在は実験的プロトタイプの構想・検証段階にあります。

## 第一段階の到達目標

まずは、次の構成による一連の動作を実機で検証します。

- **PC用アプリ**：連絡事項の入力と確認状況の表示。Webアプリまたはデスクトップアプリを検討中。
- **バックエンド**：情報の保存・振り分け、Claude APIへの解析依頼、通知と確認履歴の管理。
- **Claude API**：文章の解析・分類、受信者向け情報の整理。
- **Androidアプリ**：SDKで開発し、まずはスマートフォン1台へインストール。個人向け情報の表示と「確認しました」の応答。

**想定する最小の流れ：**

1. PCから架空の連絡事項を入力する。
2. Claude APIで内容を解析・分類する。
3. 必要な架空の職員へ情報を振り分け、Androidアプリに表示する。
4. 職員が「確認しました」を押す。
5. 確認結果をバックエンドに保存し、PC側にも反映する。

バックエンドの配置場所や通信方式などの技術選択は、今後の検証を通じて決定します。

## 重要事項：実験的開発と個人情報の取扱い

本プロジェクトは、介護現場における情報の集約・判断・伝達の可能性を検証する、ハッカソン用の実験的プロトタイプです。

開発・検証段階ではAnthropicのClaudeなど外部AIを使用するため、利用者・職員の氏名、属性、予定、連絡事項等はすべて架空のシミュレーション用データとします。**実在する利用者・職員の個人情報は使用せず、外部AIに入力しません。**

将来、実際の介護現場で運用する場合には、個人情報保護と情報管理の観点から、施設内の管理環境で稼働するローカルLLMの利用を基本構想として想定します。ただし、ローカルLLMの採用だけで安全性や法令適合性が保証されるものではなく、アクセス権限・データ保護・監査・施設の承認などを別途設計する必要があります。

なお、日本の個人情報保護法は外部AIの利用を一律に禁止しているわけではありません。実運用においては、情報の利用目的やサービス提供者のデータ取扱い等を確認し、法令・契約・施設方針に照らして慎重に検討します。

今回のハッカソンは仕組みの実現可能性を示す段階であり、**実在の個人情報を処理する運用を目的としません。**
