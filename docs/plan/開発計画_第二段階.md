# HEART RELAY 第二段階 開発計画（2026-11-05 承認・着手）

オーナー指示（2026-11-05「追加開発GO・マルチエージェント実装指示」）に基づく。提出期限 **11/8 20:00 JST**。機能追加停止は **11/7 午前**。
API 契約は `docs/api.md`（v2）を正とする。v1 の経路（PC→Claude→Android→確認→PC）は壊さない。

## 1. 採否と設計要点

| 優先 | 項目 | 方針 |
|---|---|---|
| P0-1 | スマホ・PC からの直接テキスト入力 | 既存 Web を **レスポンシブ化**し、スマホのブラウザから同じ画面で入力・確認・承認できるようにする。Android アプリは無変更（受信専用のまま）。Pixel からは Wi-Fi で `http://192.168.0.206:8787/`、または `adb reverse` 経由 `http://127.0.0.1:8787/` |
| P0-2 | 200名台帳連携 | `fixtures/` を起動時に取り込み `residents` を 200 名に置換。連絡文から **決定的照合**（ID／氏名／カナ／姓）。自動確定は ID 一致か同姓同名の無い完全一致のみ、それ以外は `needs_resident` で職員が候補から選ぶ。Claude には確定 1 名の台帳情報＋職員名簿のみ渡す。職員 20 名 ⇄ 台帳職員 15 名の対応は `fixtures/README.md` の表どおり（`ledger_staff_id`） |
| P0-3 | フロア共有タブレット画面 | Analysis に `audience`（個別／全体／両方）と `board_post` を追加。承認時に `board_posts` へ保存。`/board.html` を iPad 等のブラウザで全画面表示（5 秒更新、大きな文字、確認操作なし＝個別確認履歴と区別） |
| P0-4 | ファイル取り込み | `POST /api/intake`。画像・PDF は Claude の画像／文書入力で転記（推測禁止）、TXT（UTF-8／Shift_JIS 判定）・DOCX（mammoth）・XLS/XLSX（SheetJS、**マクロは読まない・実行しない**、シートごとに表として抽出）はローカル抽出。抽出テキストを画面で **確認・修正してから** 解析へ。元ファイルは連絡事項に紐づけ保存 |
| P1 | マイク音声入力 | P0 完了後。Chrome の Web Speech API で口述→テキスト→確認→解析。録音ファイルの文字起こしは **未実装と明記** |
| P2 | 再通知 | 余力があれば |

## 2. 担当分配（並列・担当ファイルを分離）

| 系統 | モデル | ブランチ | 担当ファイル | 内容 |
|---|---|---|---|---|
| A 台帳・解析コア | **Opus** | `feat/ledger-analysis` | `backend/src/ledger/*`, `routes.js`, `seed*.js`, `db.js`(residents/messages 列), `analyzer/*`, `test/api.test.js`, `test/ledger.test.js` | 200名取り込み・照合・`needs_resident` フロー・Analysis v2（audience/board_post/excluded）・プロンプト・mock 対応・send で `insertBoardPost` 呼び出し・デモ文更新 |
| B 共有ボード | Sonnet | `feat/board` | `backend/src/board/router.js`, `web/board.html`, `web/board.js`, `web/board.css`, `test/board.test.js` | `/api/board`・archive・タブレット全画面ページ |
| C ファイル取り込み | Sonnet | `feat/intake` | `backend/src/intake/*`, `backend/package.json`, `test/intake.test.js`, `test/fixtures/*` | multipart 受信・種別判定・ローカル抽出・Claude 転記・保存 |
| D Web（入力・提案・状況） | Sonnet | `feat/web-v2` | `web/index.html`, `web/app.js`, `web/styles.css`, `web/dev/*` | レスポンシブ化、職員選択、ファイル添付→抽出確認、利用者候補選択、audience／board_post 編集、対象利用者の手動変更 |
| 統合・検証 | Fable | `main` | — | 契約・骨組み（済）、レビュー、マージ、E2E、実機検証、記録 |

依存: B/C/D は契約（docs/api.md）だけに依存し、A と並行する。D は `web/dev/mock-server.mjs` を v2 契約へ更新して単体で動かす。
