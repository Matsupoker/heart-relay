# 起動手順（第一段階デモ環境）

PC 1台（Windows）＋ Android 実機 1台で、「入力 → AI解析 → 個別配信 → 確認しました → PC反映」を動かす手順です。
**扱うデータはすべて架空です。**

## 0. 必要なもの
- Windows PC: Node.js 22 以上（`node -v` で確認）
- Android スマートフォン（Android 8.0 / API 26 以上）
- PC とスマホが同じ Wi-Fi に接続されていること
- Claude API キー（無い場合はモック解析で動きます）

## 1. バックエンド＋PC画面を起動（Windows PC）
```
git clone https://github.com/Matsupoker/heart-relay.git
cd heart-relay\backend
npm install
copy .env.example .env
notepad .env        ← ANTHROPIC_API_KEY=sk-ant-... を記入して保存（モックで試すなら空のまま）
npm run seed
npm start
```
ブラウザで http://localhost:8787 を開くと PC 画面（ホーム）が出ます。画面下部のフッターにあるバッジが「Claude API（モデル名）」なら本番解析、「モック解析」ならキー未設定です。

### PC 画面の構成（UI刷新 2026-11-07 以降）
| 画面 | URL（ハッシュ） | 内容 |
|---|---|---|
| ホーム | `#/home`（既定） | 「連絡事項を送信する」、本日の配信件数・未確認件数・確認完了件数、「今日の連絡」一覧 |
| 新規連絡 | `#/new` | 入力 → AI 提案 → 承認（PC は 2 カラム、スマホは縦積み）。サンプルボタンもここにあります |
| 配信管理 | `#/deliveries`、`#/deliveries/<id>` | 連絡の一覧と詳細。職員別の確認状況、AI の選定理由 |
| 共有ボード | `board.html`（新しいタブ） | フロア掲示用。サイドナビから開きます |

スマホ（幅 900px 以下）では上部に「＋新規連絡」、下部に固定タブ（ホーム／新規／配信／ボード）が出ます。

初回起動時に Windows のファイアウォール確認が出たら「プライベートネットワーク」を許可してください。出なかった場合は管理者 PowerShell で:
```
New-NetFirewallRule -DisplayName "HEART RELAY 8787" -Direction Inbound -Protocol TCP -LocalPort 8787 -Action Allow -Profile Private
```

## 2. PC の IP アドレスを調べる
コマンドプロンプトで `ipconfig` → Wi-Fi アダプターの「IPv4 アドレス」（例 `192.168.1.23`）。
スマホのブラウザで `http://192.168.1.23:8787/api/health` を開き、JSON が表示されれば LAN 疎通 OK。

## 3. Android アプリをインストール
- 配布された `heart-relay-debug.apk` をスマホにコピーして開く（「提供元不明のアプリ」の許可が必要）、または USB デバッグで `adb install -r heart-relay-debug.apk`
- 自分でビルドする場合は `android/README.md` を参照

## 4. アプリの初期設定
1. 起動 → サーバー URL に `http://192.168.1.23:8787`（手順2のIP）を入力 → 「接続確認」
2. 職員一覧から 1 名を選ぶ（例: 運転手「竹内 康介」）
3. Android 13 以降は通知の許可ダイアログで「許可」

## 5. デモの流れ
1. PC で `#/new`（新規連絡）を開き、入力欄のサンプルボタン「青木様（r01）は本…」→「AIで解析する」
2. 右側に AI 提案（分類・緊急度・宛先候補と職種別の本文）が出る。内容を確認・修正して「承認して配信」→ 配信詳細（`#/deliveries/<id>`）に移ります
3. スマホに通知が届く → 開いて「確認しました」
4. 配信詳細の職員別確認状況が数秒以内に「確認済」に変わります（配信管理の一覧とホームの「今日の連絡」にも反映されます）

## トラブルシューティング
| 症状 | 確認すること |
|---|---|
| スマホから接続できない | 同じ Wi-Fi か／PC のファイアウォール／IP の打ち間違い／ルーターの「AP アイソレーション（プライバシーセパレーター）」が有効だと端末間通信が遮断されます |
| 解析が `failed` になる | バックエンドのコンソールのエラー文（API キー・モデル名・残高）。「再解析」で再試行 |
| 通知が来ない | アプリを前面に出したままにする（第一段階は前面時のみポーリング）。通知許可を確認 |
| 429 が出る | 1 分あたりの解析上限（既定 10 回）。少し待つ |

## v2 での追加事項

### A. スマホからの入力（一般職員の入力画面）
- **同一 Wi-Fi の場合**: スマホの Chrome で `http://<PCのIP>:8787/` を開く（例 `http://192.168.0.206:8787/`）。ホームが開くので、下部タブの「新規」から入力します。
- **USB 接続の場合**: PC で `adb reverse tcp:8787 tcp:8787` を実行したうえで、Pixel の Chrome から `http://127.0.0.1:8787/` を開く。

### B. フロア共有ボード（タブレット）
- タブレットのブラウザで `http://<PCのIP>:8787/board.html` を開き、全画面表示にする。

### C. ファイル取り込みの対応形式
- 画像（PNG / JPEG / WebP / GIF）・PDF: Claude で内容を転記（Claude API キーが必要。未設定時はモック解析）。
- TXT / DOCX / XLS / XLSX: ローカルで文字を抽出（Claude は呼ばない）。マクロは実行しない。
- ファイルサイズは 20MB まで。

### D. 初回起動時の DB 移行について
- 既存の DB（v1）がある場合、起動時に自動で v2 形式へ移行します。
- 移行後は利用者（resident）が**架空の 200 名**になります。v1 のデータは架空データのみですが、移行前後で一覧が変わることに注意してください。

### E. テスト
| コマンド | 内容 |
|---|---|
| `npm test`（backend フォルダ） | バックエンドの単体テスト |
| `node web/dev/mock-server.mjs` → 別ターミナルで `node web/dev/e2e.cjs` | モックサーバに対する E2E（先にモックサーバを起動） |
| `node web/dev/e2e-real.cjs`（リポジトリ直下） | 実バックエンド（mock 解析・一時DB）に対する統合 E2E。Claude 解析は呼ばない |

### F. 音声入力（新規連絡画面）
- 「音声で入力」ボタンを押すと、ブラウザ標準の音声認識（Web Speech API、日本語）で話した内容が連絡内容の欄に追記されます。もう一度押すと停止します。
- 認識結果は自動では解析・送信されません。内容を確認・修正してから「AIで解析する」を押してください。
- 録音ファイルは保存せず、このアプリのサーバーにも送りません（認識はブラウザ／OS 側のサービスが行います。Chrome ではブラウザ提供元の音声認識サービスに接続します）。
- マイクの許可が必要です。拒否した場合や非対応ブラウザでは、メッセージが表示され、手入力はそのまま使えます。
- 他の画面へ移動したとき・配信が成功したときは録音を停止します。
