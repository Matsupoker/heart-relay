# HEART RELAY（仮）｜導入範囲と将来拡張の検討メモ（2026-11-02）

> 出典: Google Docs（2026-11-02 取得、参照用に転記）。構想段階／実装方式は未確定。

## 1. 位置付け
初期プロトタイプと将来構想を整理する覚え書き。システム構成を一つに固定しない。

## 2. 初期検証の対象
デイサービス1事業所・架空職員20名（事業所長1、PT2、看護師2、生活相談員1、運転手2、介護職員12）。検証端末: Windows PC 1、iPad mini 5 1、Android 3。

## 3. 将来構想（方向性）
複数事業所を擁する組織をモデルに、事業所をまたいだ情報伝達への拡張可能性。組織内管理環境にローカルLLMの中央サーバーを置き、各事業所から集約→AI分析・分類→適切な事業所・職種・担当者へ振り分け、という構成が一例。中央集約型・単一LLMを確定するものではない。

## 4. 両方向に進める設計方針
- 選択肢A: 単一事業所で完結する運用
- 選択肢B: 複数事業所にまたがる運用・中央管理
- 初期プロトタイプはAで検証。後にBへ拡張できるよう、**法人・事業所・職員などの識別情報や情報の共有範囲を分離して考える**。Bはハッカソン必須要件ではない。

## 5. 未決定事項
主軸（単一/複数事業所）、ローカルLLMの配置・構成、事業所間共有範囲とアクセス権限、AI/人間の判断範囲、通知優先順位・確認記録・誤配信防止・監査ログの設計。

## 6. 個人情報の取扱い
架空データのみ。実在個人情報を外部AIへ入力しない。ローカルLLM採用だけで法令適合・安全性は保証されない。
