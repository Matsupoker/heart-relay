# HEART RELAY（仮）｜第一段階の到達目標・初期システム構成（2026-11-02 検討版 v0.1）

> 出典: Google Docs（2026-11-02 取得、参照用に転記）。完成仕様・採用技術を確定するものではない。

## 1. 目的
PC管理画面、Android実機アプリ、Claude API解析を、バックエンドを介して一連の仕組みとして動かす。「入力 → 解析・分類 → 必要な職員への伝達 → 確認の記録」まで通す。

## 2. 初期構成
① PC用アプリ（Web/デスクトップ未決定） ② Androidアプリ（SDKで開発、所有するメインAndroid 1台に実機インストール。表示と「確認しました」） ③ バックエンド（保存・振り分け・Claude API依頼・確認履歴） ④ AI処理（第一段階はClaude API。将来ローカルLLM）。
バックエンド稼働場所: Windows PC内 or クラウド（未選定）。

## 3. 最小実証シナリオ（架空データ）
1. PCから「A様は受診のため15時までに帰宅が必要」を入力
2. バックエンドがClaude APIへ解析依頼
3. Claudeが「受診」「送迎」「時間変更」等に分類し、送迎担当者向け内容を整理
4. バックエンドが対象職員に紐づけて保存し、Androidアプリへ届ける
5. Androidで表示→職員が「確認しました」
6. 確認職員・対象通知・確認時刻が保存され、PC管理画面で確認済み表示

## 4. 完了判定
- PCから架空の連絡事項を登録できる
- バックエンドからClaude APIを呼び出し解析結果を受け取れる
- Android実機にアプリをインストールしバックエンドと通信できる
- 特定の架空職員向けに選別した情報をAndroidに表示できる
- 明示的な確認操作が履歴保存され、PC側に反映される
PC1台・Android実機1台で再現できれば到達。

## 5. 対象範囲
扱うもの: 1事業所の架空データ、PC文字入力、AI分類、特定職員配信、確認履歴、Android⇄バックエンド双方向通信。
含めないもの: 職員20名・Android複数台・iPad共有ボードの全体再現、音声/写真送信・文字起こし/OCR、プッシュ通知本格運用、複雑な権限・シフト連動、ローカルLLM、複数事業所連携、実導入。

## 6. 設計上の原則
- 架空データのみ
- Claude APIキー等の秘密はバックエンドのみ。公開GitHub・Androidアプリに埋め込まない
- AI処理の呼び出し口を独立させ、ローカルLLMへの切替余地を確保
- AI提案と人間承認の境界は未決定。無条件の自動配信を前提にしない
- 送信・表示・明示的確認・業務完了を混同しない。第一段階は「確認しました」まで

## 7. 今後決定する技術事項
バックエンド設置場所・通信方式、PC画面方式、Android通信・配信方法（ポーリング/プッシュ）、DB・職員識別・最低限の認証、AI出力形式・送信先確定手順・人間確認の位置づけ。
